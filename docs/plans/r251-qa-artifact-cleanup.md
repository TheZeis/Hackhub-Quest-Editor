# r251 — QA-artifact cleanup: what is temporary, what is load-bearing

**Zeis's observation, which this plan acts on:** *"All the QA stuff is just
that — temporary QA stuff. I have a feeling previous agents started treating
them as if they were part of the editor, rather than us testing things and
getting rid of them when we didn't need them any longer. There are a lot of
stale files in the repo now that need cleaning up."*

He is right, and the mechanism is worth naming because it explains why the pile
grew: **every QA folder in this repository is pinned by a test**, so deleting
one has always meant deleting tests in the same commit. Nobody did, so both
halves accumulated.

- `reference/sdk-0.24-qa/` — **47 files, 1.3 MB** (of a 17 MB working tree).
- **82 of 1,894 tests (4.3%)** exist to assert the contents of QA artifacts, and

## Proposed, needing Zeis's call

Each of these removes a test file or a checked-in artifact, so none of them
should happen on an agent's initiative.

### 1. Retire the ModSettings probes — `modsettings/`, `modsettings-v2/`, 7 tests

The question is **answered**: the settings UI is in the main menu, the whole
declare → render → change → persist → read-back loop is proven, MS-07 is red
and that is a real answer. The evidence lives in `STATUS.md`; the probe folders
and their 7 tests no longer earn their place. What the editor owes is the reset
affordance MS-07 implies, which is a Next-up row, not a probe.

### 2. Retire the feed canary — `feedcanary/`, and its rows in `sdk024QaScaffold`

Closed in r225. Nothing can learn anything new from it.

### 3. Stop checking in `editor-export/` — 552 KB, 9 tests

This is a **build artifact in git**, regenerated by `npm run gen:qa-export`,
with a byte-for-byte guard test whose only job is to notice when the two drift.
That guard has real value — it caught exactly that in r175 — but the value is
in the *script*, not in the committed bytes. Options:

- keep as is (status quo, costs 552 KB and 9 tests);
- generate on demand and let the guard run in CI only;
- keep the guard but stop committing the output, so a stale export cannot exist.

### 4. Decide what a "results" file is for

`QE24-TestResults*.md` (7 files) are Zeis's raw pasted logs and observations.
They are the most valuable thing in the folder — r250's audit could only
disprove two rounds' conclusions *because* those raw logs were still here. They
should be kept. What should not be kept is the layer of confident summaries
written on top of them (`STATUS.md` verdict rows, README roadmap rows) once
those summaries are contradicted; r251 corrected the ones in scope.

### 5. The structural rule, if Zeis wants one written down

- **One live probe per open question.** When the question closes, the probe
  folder, its tests and its zip go in the same commit, and the evidence stays
  in `STATUS.md` + the raw results file.
- **Never commit a build artifact.** Zips and `editor-export/` are outputs;
  their sources are the folders and the compiler.
- **A test that asserts the content of a hand-written probe is scaffolding, not
  a safety net.** It protects nothing the editor ships. It is worth writing
  while the probe is being built (it is how the probe gets falsified) and worth
  deleting the day the probe is.

The `.gitignore` exception `!reference/sdk-0.24-qa/*/dist/` — added in r239
because losing those files to a clean checkout silently broke the QA tests — is
a symptom of the same coupling, and can go if items 1–3 are taken.
