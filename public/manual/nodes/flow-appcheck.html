App Install Check

Flow control  flow.appcheck

What it does

Checks the player's desktop and sends the story down Installed or Missing. It can also save their whole list of installed apps at the same time, so something later can read it.

When you'd use it

Use it before your quest sends the player to an app. Most apps are not installed on a fresh save. The player unlocks them as they play. A quest that tells a player to open an app they lack can look broken.

Use it to avoid a dead end. Send players who have the app one way. Give everyone else a different route or a nudge.

Turn on Also save the list of installed apps when a later Branch needs to test the list. It can also help a message name the apps the player owns. To see which apps the game counts on your save, send the list to a Notify. Read the Notify in game.

In the game, this looks like

Nothing appears on screen. The player only notices that the story took the path that matches what is on their desktop.

Fields

App name

Pick an app the desktop knows, or type another exactly as the desktop spells it — a spelling it does not use never matches. Terminal commands cannot be checked here; the editor says so if you type one.
What to put here
Pick one from the list — those are the apps the desktop reports, so a pick can never be misspelled. If yours is not there, type it and make it match the desktop exactly, capitalization included. The editor warns you if you type a terminal command, because those can never be checked here.
Default
empty
Limits
One of the 9 listed below.
If you leave it empty
With no name there is nothing to look for, so the <b class="ui">Missing</b> path always runs. The editor warns you while you are still looking at the field.

Also save the list of installed apps

Stores every app the player has, so a later Branch can test the list or a message can mention what they actually own. Also the quickest way to see which apps the game counts on your own save — send the list to a Notify and read it in game.
What to put here
Stores every app the player has under the name below, then carries on with the check as normal. The node does both.
Default
on
Limits
On or off.
Watch out
It is on by default. Keeping the list costs nothing. It is the only way to see which apps the game counts. Turn it off if no part of the quest reads it.

Save the list as

The name the list is stored under. Two checks using the same name refresh it, which is what you want after the player unlocks something.
What to put here
Anything you like. Other parts of the quest use this label to find the list again. The player never sees it.
Default
"installedApps"
Watch out
Two checks using the same name refresh it, which is what you want after the player unlocks something. Use two different names if you want to keep a snapshot of each moment.

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find App Install Check under Flow control in the palette.
  2. Drag it onto the canvas where the story should depend on an app.
  3. Wire the previous node into In.
  4. Type the app's name as the desktop spells it.
  5. Wire both Installed and Missing somewhere. Neither may be left empty.

Common mistakes

  • One output is left unwired. A player whose desktop takes that path reaches a node that goes nowhere and the quest stalls. The editor flags it as Dead end.
  • The name does not match the desktop's. The check is by name, so a spelling the desktop does not use always comes back Missing. Terminal commands are not desktop apps — lynx is something the player types, not something on their desktop.
  • Assuming every player has the same apps. Apps are unlocked as the player earns them, so two players on the same quest can legitimately take different paths. That is the point of the node.
  • Checking a terminal command such as lynx. Terminal commands are installed with apt-get install, but the game does not count them as apps. Even with lynx installed, the check reads Missing — verified in game against a Kisscord control that read Installed. The node can only route on desktop apps.

Messages you might see

  • Dead end. An Installed or Missing output has nothing wired to it
  • Unreachable. Nothing leads to this node, so the check never happens
  • No app name. App name is empty, so the Missing path runs every time

Related nodes

  • Branch — Sends the story down one of two paths.
  • Wait — Pauses the story.
  • Timer — Fires the next node at a later in-game time. Choose a delay, a clock time N in-game days from now, or a fixed in-game date.
  • Reroute — A tidy point for your wires.
  • Random pick — Picks one path at random.
  • Sequence — Fires several outputs in order.
  • Debug probe — Prints what is happening here.
