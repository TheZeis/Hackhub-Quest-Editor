Branch

Flow control  flow.branch

What it does

Splits the story in two. One path runs when your condition holds, the other runs when it does not.

When you'd use it

Use it when the story should differ based on something the player did. For example, whether they were spotted, whether they paid, or which file they pulled.

Both paths need somewhere to go. A branch with an unwired Yes or No is a dead end the player walks into.

For three or more outcomes, chain branches. Each one splits again, and the canvas stays readable.

In the game, this looks like

Nothing appears on screen. The player only notices that the next message differs from the one their friend got.

Fields

Test against

Test against details from the event that fired, or against quest data you stored earlier with a “Set quest data” node.
What to put here
Choose based on where the information comes from. Pick Details from the event for values sent with the game event. Pick Quest data for values saved earlier using Set quest data.
Default
"event"
Limits
One of the 2 listed below.
Watch out
Pick Quest data when the thing you are testing happened earlier in the quest. The event that woke this branch only carries its own details.
ChoiceWhat it is stored as
Details from the eventevent
Quest datadata

Take the “Yes” path when

All clauses must hold for the “Yes” path. Otherwise the “No” path runs.
What to put here
Add one clause per thing that has to be true.
Default
an empty list
If you leave it empty
With no clauses, there is nothing to fail. The Yes path always runs, and the No path never does.

Wires

SocketDirectionWhat to connect
Ininput Whatever should run immediately before the split.
Triggerinput The event that wakes the branch, when it should react to something the player does.
Yesoutput The path that runs when every clause holds.
Nooutput The path that runs when any clause fails.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find Branch under Flow control in the palette.
  2. Drag it onto the canvas where the story should split.
  3. Wire the previous node into In.
  4. Pick what to test under Test against, then add your clauses.
  5. Wire both Yes and No to somewhere. Neither may be left empty.

Common mistakes

  • One path is left unwired. The player reaches a branch that goes nowhere and the quest stalls. The editor flags it as Dead end.
  • The condition tests the wrong source. Using Quest data while Test against says Details from the event leaves nothing to match. The No path then always runs.

Messages you might see

  • Dead end. A Yes or No socket has nothing wired to it
  • Unreachable. Nothing leads to this node, so the split never happens

Related nodes

  • App Install Check — Asks the game whether the player has an app, and splits the story on the answer.
  • Wait — Pauses the story.
  • Timer — Fires the next node at a later in-game time. Choose a delay, a clock time N in-game days from now, or a fixed in-game date.
  • Reroute — A tidy point for your wires.
  • Random pick — Picks one path at random.
  • Sequence — Fires several outputs in order.
  • Debug probe — Prints what is happening here.
