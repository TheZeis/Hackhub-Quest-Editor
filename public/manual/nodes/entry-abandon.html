On quest abandoned

Quest lifecycle  entry.abandon

What it does

Runs if the player abandons the quest. Use it to tidy up whatever the quest left behind.

When you'd use it

Use it when the quest leaves something behind that should be undone if the player abandons it. For example, a machine left unlocked or a contact left waiting mid-conversation.

Most quests do not need it. If nothing has to be undone, delete the node rather than leaving it sitting there empty.

In the game, this looks like

The player drops the quest and this fires. Anything you wired after it runs once, and the quest is gone.

Fields

This node has nothing to configure. It marks a moment in the story and runs whatever is wired after it.

Wires

SocketDirectionWhat to connect
Outoutput Whatever should happen after this node runs.

Then runs next When tests a condition Unlocks opens an objective Data carries a value

A wire only joins two sockets of the same colour, and the editor draws the wire in that colour. That is what the colours are for: match the colours and the connection takes, mismatch them and it will not.

Step by step: add this node to a quest

  1. Find On quest abandoned under Quest lifecycle in the palette.
  2. Drag it onto the canvas.
  3. Wire the cleanup to its Out socket.

Common mistakes

  • Cleanup is wired to Quest start instead. That runs when the quest begins, which is the opposite of when you want the tidy-up.
  • Nothing is wired to Out. Delete the node. An empty one only adds an Empty warning to your status bar.

Messages you might see

  • Empty. Nothing is wired to Out, so the node does nothing

Related nodes

  • Quest start — Runs once, when the quest is claimed.
  • On start & reload — Runs on claim, and again on every load.
  • On quest complete — Runs after the quest is completed.
