Feature guides

One page per surface — how to get there, and what to do once you are.

One page per surface of the editor, in the order you meet them. Each section says what the thing is for, what is on it, and what goes wrong when you ignore it. Where a setting has a consequence you cannot see, the consequence is stated.

The inspector's three tabs

The panel on the right holds three tabs, and one of them is disabled until you need it.

Node
Every field on the node you have selected. Greyed out when nothing is selected, because there is nothing to show.
Quest
Settings for the quest you are looking at. This is the default tab, so it is what you see on an empty canvas.
Mod
Settings for the whole file: the name on the box, the version, the icon.

The panel can also leave the side of the window. Drag its left edge outward and it floats, which helps when a node sits underneath it. Drag the title bar to move it and the bottom-right corner to resize it.

The floating panel and the docked one are the same inspector. The fields are identical either way, so nothing is hidden in one mode. The editor also keeps the floating panel inside the window, so you cannot lose it past an edge.

Quest settings

Six groups. Most quests need four of them.

Identity

Quest identifier
Internal. Unique across your mod, and the thing other quests name when they start this one.
Display title
What the player sees in their quest list.
Description
The pitch shown before the player accepts. Use it to name any game mod the quest needs.
Journal group
Folders the player's journal into groups. Two quests in the same group read as one story.

Hackhub feed post

The toggle that puts the quest on the Hackhub feed as a job the player can accept on the spot. It is the organic way to be found. The scripted Claim another quest node covers quests the story starts itself. Quests accepted from the feed complete from the post itself, not the journal.

Post this quest to the Hackhub feed
Off (the default) ships no post at all.
Post text
The feed body — the pitch the player accepts.
Poster name
Who seems to have written the post. Blank, the game generates a name. Your own reads best when it is tied to the story rather than a name anyone could have.
Poster avatar
A PNG or JPG. Blank, the game draws one — a mod that ships no avatars still looks at home on the board.
Likes
Cosmetic. In-demand jobs have likes; desperate ones do not, and sometimes that is the fiction.
Comments
Any number, each with a name, an optional drawn or uploaded avatar, and a line of text.

About the game-generated persona: every field you leave blank is filled by the game. It supplies a generated name and a drawn avatar. A post with nothing set still looks like it belongs. Feed posts are part of the quest's registration. There is currently no way for a mod to take one back down. asking the game's developers for that is on the list.

Rewards

Money and XP, both plain numbers. These are what the game pays for finishing the quest. That is separate from anything a Pay the player node does mid-story.

Behaviour

Start automatically
The quest begins on its own instead of waiting to be accepted.
Complete automatically
The game closes the quest once its objectives are done. Leave it off when a Complete quest node decides the ending. See how quests finish.
Player can abandon
Lets them give up. Turning it off also means On quest abandoned never runs.
Show a manual complete button
Puts a button in the player's hands and lets them decide when the quest is over.
Tidy the objective list when the story ends
Clears completed objectives so the panel is not a scroll of old text.
Closing line
One sentence shown when the quest ends. Use it with the legacy tidy-up option, or as the final visible line before a Complete quest node.

Employer

First name, Last name and E-mail. The person the quest is from. Worth filling in, because a job with no name behind it reads as a system message.

Health

Not a setting. This group counts your objectives and flags those without a When event wire. It does not count story wires: a regular Objective can still tick when the story reaches it. Treat the count as a prompt to check the route, not proof that the objective cannot finish. See the Health message.

Mod settings

These describe the file, not the story. Everything here ends up on the card the game shows the player.

Mod id
Internal, and part of the exported file's name. Changing it later makes the game treat the result as a different mod.
Display name
The name on the box.
Version
Also part of the filename, which is how two builds of one mod avoid overwriting each other.
Author
Your name. Defaults to the editor's name if you leave it.
Description
The blurb in the mod list.
Cover image
and Icon — the two pictures. Both optional, both shipped inside the .zip.
Tags
Search terms for the mod list.

Dialogues

The Dialogues button opens the phone conversations, in one place rather than scattered across the canvas. This is where you write who says what, in what order, and with what delay.

If nothing leads there, the canvas can flag the node as unreachable. Do not rely on the export report to catch it.

Websites

The Websites button opens the builder. Your sites are on the left, and the pages of whichever site you picked on the right. A site is a host; a page is a path on it.

Each page has a live preview beside the editor, so you see roughly what the player will see.

Web addresses can overlap. Two sites in one mod that use the same host can compete over the same address. The export report checks for duplicates in this mod, but cannot inspect other installed mods. Give each site its own distinctive host. A page can also be unlisted. It stays out of game search. A player may still reach it by address, a link or a brute-force tool. Unlisted does not mean private.

Templates

The picker has fourteen entries: twelve templates and two Reference sheets. Each card shows difficulty and node count. The window also offers Export current quest and Import a quest file.

Loading a template replaces the current project and clears undo history. Autosave is not a versioned backup, so save a project file before experimenting.

Here is every card in the picker. The summaries name the kind of work each one teaches, not its plot. The first twelve are starter quests; the last two are lookup sheets, not quests to edit.

  • Blank quest — Beginner · 4 nodes. Start with the basic quest entry points and build everything else yourself.
  • First Contact — Beginner · 8 nodes. A short, straightforward quest with one objective and a clear finish.
  • The Byline — Beginner · 11 nodes. Follow clues through a website and a writer lookup.
  • Cold Call — Beginner · 10 nodes. Learn how conversation, hints and a typed answer can carry a quest.
  • The Harbour Manifest — Advanced · 22 nodes. A compact reconnaissance and server-access route.
  • The Help Desk Leak — Advanced · 23 nodes. Use public website clues to reach a hidden page.
  • Bad Attachment — Advanced · 14 nodes. Build a mail-led story that depends on a player's reply.
  • Six Tries — Advanced · 23 nodes. A terminal-focused route through scanning, login recovery and SSH.
  • Dead Air — Advanced · 28 nodes. Mix phone, chat, timed waits and repeated choices.
  • Cold Storage — Expert · 20 nodes. Follow a longer network route into a database.
  • The Ledger Contract — Expert · 33 nodes. Trace a network route and use different access steps.
  • The Long Game — Expert · 36 nodes. A three-part campaign with linked quests and different endings.
  • Node Reference — Reference · 51 nodes. A read-only canvas showing the node types and example fields.
  • Quest Cookbook — Reference · 16 nodes. A read-only guide to techniques used in the game's quests.

Choose a template to learn from. Use Export current quest and Import a quest file to move work between projects.

Dry run

The Dry run button walks through your quest the way the exported mod would run it, without installing anything. It is the closest thing to a test drive the editor has. It runs the editor's emitted mod against a small recording version of the game's tools.

Watch the order and which path the run takes. A missing node may have no wire, or this run may have taken another branch.

Read the results carefully

Opening Dry run starts a run. After you edit the quest, choose Run again. The dialog lists the story steps it reached, then shows how each objective completed or what its event check found.

  • would tick. The listener matched a sample shaped from the condition you wrote. It does not prove that the game will send that event.
  • would never tick. The simulator found no matching listener or the sample did not satisfy the condition. Read the note beside the objective and check its event, detail and value. If the note says the listener threw, copy that full message too.
  • unknown event. The event is not in the simulator's built-in event list. A community addon's event can still be real; the dry run cannot test it.
  • internal beat. The event belongs to the quest's own story flow, rather than a tool the player uses.

The list at the top also includes export warnings. An error beside a quest means it did not register or its code threw while starting. An error above the quest list means the mod could not be prepared or failed while registering. Copy the full message and build stamp if you need help.

If the dry run itself reports an error

  • the compiler produced no dist/mod.js — nothing to dry-run
    means the editor did not create the mod file. The dry run needs it. Copy the full message and build stamp if you ask for help.
  • the emitted mod threw while registering means the mod failed while setting itself up. The rest of the report may be incomplete.
  • this quest did not register means the simulator could not find that quest in the mod it loaded.
  • the quest's own code threw means that quest failed while its opening steps ran. Keep the full text after the colon; it may name what failed.
A dry run is a rehearsal, not a game test. It uses sample event details, not events emitted by the real game. It collapses waits instead of waiting through in-game time, and it does not use the game's tools or show its screens. A random choice follows the simulator's sample path; other runs in game can take another path. Test timed conversations, scans, exploits, community events and other game-dependent steps in the actual game.

Addons

Addons are packs made by other people that add events and tool actions to your editor. The window's own description of them:

Community addons drop in here as data: their events join the trigger picker, their quest data becomes nodes. Addons are data only — the editor never runs code from them.

Once a pack is loaded, its events show up in the trigger picker under Community addons. Its actions appear in a palette group that starts with Editor Mods and ends with the pack name. Nothing changes until you load one.

Your players need the related game mod too. Features that depend on an addon may not work for players who have not installed the game mod it drives, and the game may not explain what is missing. Name that requirement in your quest description — the editor can remind you, but it cannot write the description for you.

If an addon will not load

Open Addons, then choose Load a pack (.json) or drop the file into the window. An addon file holds information. The editor reads that information; it does not run programs from the file.

A typing mistake in the file
[file name]: this is not valid JSON — check for a trailing comma or a stray character.
Get a fresh copy, or send the message to the addon author.
The file is not an addon
It may be a text file, but it does not contain one complete addon. Ask the author for the full toolpack.json.
The format number is wrong
This editor accepts version 2 of the addon file. The file uses another version. Ask the author for an updated toolpack.json; changing your quest will not fix this.
A short path and message are shown
The addon is missing a detail or has one the editor cannot use. The dotted path tells you where the problem is in the file. Send the whole message to the addon author instead of editing the file yourself.
The file could not be read
Try selecting it again from your computer. If it still fails, download or copy the file again.
No addon files were selected
The picker only accepts files ending in .json. Choose the addon file, often named toolpack.json.

The editor shows at most four problems at once. If the file still will not load, ask the addon author to check the rest.

You can select several files at once. A good file can load even when another one fails; the result line reports both. Loading applies immediately. Choose Save to close the window; this does not save your quest project.

Keep the original addon file. Addons are saved in this browser, not in your project. The window gives each addon an ID, a label that identifies it. Loading another file with the same ID replaces the loaded addon. If browser storage fails, the addon lasts only for this session. An invalid saved addon can be skipped on the next visit without a separate warning. If an addon disappears, load its original .json file again.

Settings

The Settings button holds editor preferences. None of them reach your quest or the exported mod; they change how the editor looks and feels for you.

Canvas
Show grid, Grid colour, Grid opacity, Grid scale and Snap to grid.
Wires
Animated wires, Springy wires, Line weight and Mark size.
Appearance
Interface font, with a Follow the editor theme option for the grid.
Getting out
Clear the autosaved draft and Reset all editor preferences. Both are deliberate and both ask first.

Canvas tools

Top left of the canvas. These move nodes around; none of them change what your quest does.

Tidy up
Arranges the whole graph left to right, by how far each node sits from its entry point. The one to reach for after a long building session.
Align in a row · Align in a column
Puts the selected nodes on one line, centred.
Space out across · Space out down
Equalises the gaps without moving anything onto a line. The outermost nodes stay where they are.
Springy wires
Switches the wires between settling and drifting. Purely cosmetic, and off is calmer on a big map.
Debug
Opens the editor's own diagnostics: the build stamp, wire numbers, counters and a recent-event log. This is not the Debug probe node. That one goes on your canvas and prints what a node does at runtime.

Beside the tools is the counter described in where messages appear. It reads No issues when the quest is clean.

Things outside your quests

This section covers three things a pack can add outside a quest. They are a start-menu entry, a small box on the desktop and right-click entries.

They all live in one window, opened from Extras on the toolbar. Nothing there is required: a pack with none of it exports exactly as it always did.

A start-menu entry

The start menu has a strip of entries along the bottom. A pack can add one, with a picture. It has four possible jobs. It can say something, start one of your quests, send the player a letter, or open the game's own handbook.

Picture
Optional, and worth having for a pack whose entry sits beside the game's own. Pick a picture from your machine. It travels inside the pack, so keep it small. The menu draws it the size of a letter in this sentence.
The entry's own words
The label, and the sentence a "say something" entry shows. They appear as you write them; the editor has no screen for managing translated text yet.
When it appears
As soon as the player's game loads your pack. Nothing has to be started for it to sit there.
Positions are the game's. Entries land in the bottom strip. An earlier version of the game ignored a "top" or "bottom" choice, so this editor does not offer one.

A box on the desktop

A widget is a small web page the game draws on the player's desktop. Think a note, a counter, a status board. You build it with the same editor the website builder uses, including the preview.

Size and place
Width, height and the corner it sits at, in the desktop's own pixels.
See-through
Off by default, so a widget arrives with a background. Turn it on for a widget meant to look painted onto the wallpaper.
A widget's own words are a page, not a quest. What you type inside the widget is shown as you typed it: translated words do not reach in there, because the widget is a file the game opens, not a line of text it fills in. Write those words in the language you want them in.

An entry in a right-click menu

Where a player right-clicks, a pack can add an entry. That can be on a file, on the desktop, on the taskbar, or on a window. Each entry carries a label, an optional picture, and one of the four jobs above.

Use it for the thing a player reaches for while looking at something. Think "inspect this file", "send this to my notes", or "open the walkthrough".

Translated text is not available yet

The game can show translated text, but this editor does not currently offer a screen for writing or checking translations. Text you enter in quests and pack extras is used as written; changing the game's language does not translate it. This handbook does not give steps for a feature the editor cannot currently manage.

The handbook entry, honestly

One of the four jobs opens the game's handbook. In HackHub 1.3.1, the book opens on its own landing page; it does not jump to the page you chose. The entry can still point players toward the handbook. The editor's log records which page was requested. See When something goes wrong for help finding the log.

Two buttons beside a text field

Some text fields carry one or two small buttons. They look alike and do opposite things, which is worth getting straight early.

The dice
Fills the field with a sample value, such as an address, a contractor's name or an e-mail. It becomes ordinary text in your project. It stays until you edit it or generate another value.
The sparkle
It may stand for a saved answer, player detail or generated value. The tag tells the game which one.

Roll the dice when you want something concrete to look at while you build. Use the sparkle when the game is the only thing that knows the answer. A machine address is the common case, since the game allocates it.

Both are ordinary edits. Either one can be undone with Ctrl+Z, exactly like typing.
